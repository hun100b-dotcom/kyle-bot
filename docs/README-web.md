# Capri 웹앱(PWA) — 아이폰에서 앱처럼 쓰기

> 데스크톱 앱(Electron)은 **그대로**입니다. 이 문서는 **추가로 만든 웹앱 경로**만 설명합니다.
> 웹 주소: **https://hun100b-dotcom.github.io/capri-web/**

---

## 1. 아이폰에 설치하는 법 (3단계, 1분)

앱스토어에 가지 않습니다. 사파리로 열어서 홈 화면에 얹으면 끝입니다.

1. 아이폰 **사파리**(크롬 말고 사파리)로 **https://hun100b-dotcom.github.io/capri-web/** 접속
2. 아래 가운데 **공유 버튼**(⬆︎ 네모에 화살표) → 메뉴를 내려서 **"홈 화면에 추가"**
3. 오른쪽 위 **"추가"** → 홈 화면에 **Capri 아이콘**이 생깁니다

이제 그 아이콘으로 열면 **주소창 없이 앱처럼** 뜹니다.

## 2. 업데이트는 어떻게 되나요?

**아무것도 안 하셔도 됩니다.** 설치 파일을 다시 받을 필요가 없습니다.

- 제가 새 버전을 올리면, 앱을 열 때(그리고 1시간마다) 폰이 알아서 새 버전을 확인합니다.
- 새 버전이 준비되면 화면 맨 위에 초록색 **"새 버전이 준비됐습니다 · [지금 업데이트]"** 띠가 뜹니다.
- 그 버튼만 누르면 즉시 최신 화면으로 바뀝니다. (재설치·재로그인 없음)
- 인터넷이 안 되는 곳에서도 앱은 그냥 열립니다(마지막 화면을 폰에 저장해 둡니다).

## 3. 지금 되는 것 / 아직 안 되는 것

| 기능 | 상태 | 설명 |
|---|---|---|
| 삼분할·호가창·캔들 계산 | ✅ 됨 | PC 앱과 **똑같은 계산 코드**(lib/calc.ts)를 씁니다 |
| 익절/손절가, 수량 제안 | ✅ 됨 | 시드 × 세션 비율로 살 수량까지 계산 |
| 장 상태(휴장·다음 개장) | ✅ 됨 | 주말·미국 공휴일 반영(v0.8.4) |
| 원화 병기 | ✅ 됨 | 환율은 지금 **수동 입력**(설정 탭) |
| 결과 복사 | ✅ 됨 | 복사해서 토스 앱에 그대로 옮겨 적기 |
| 현재가·환율 자동 조회 | ⏳ 2단계 | 클라우드 서버 배포 필요(아래 4번) |
| 주문 넣기 | ❌ 안 함 | 주문은 **PC의 Capri**에서만. 안전장치·확인 팝업이 거기 있습니다 |

> 이 웹앱에는 **토스 키를 넣지 않습니다.** 설정값(시드·환율 등)은 폰 안에만 저장됩니다.

## 4. 개발자용 — 왜 이런 구조인가

### 4.1 브라우저가 토스를 직접 못 부른다 (실측)

2026-08-13 확인:

- 토스 응답에 **CORS 허용 헤더가 없다** → 브라우저에서 직접 호출하면 차단된다.
- 설령 뚫려도 **Client Secret이 폰에 노출**된다. 절대 불가.

→ 그래서 시세·환율은 **서버가 대신 부르는 구조**여야 한다(`api/` 폴더).

### 4.2 클라우드에서 토스는 열려 있다 (실측)

미국 클라우드(GitHub Actions 러너)에서 **가짜 키**로 토큰 발급을 시도 → **`401 invalid_client`**.
요청이 인증 단계까지 도달했다는 뜻이므로 **IP·지역 차단은 없다**.
(403이나 타임아웃이었다면 서버리스로는 불가능했고, 고정 IP 서버가 필요했을 것이다.)
진단 워크플로: `.github/workflows/toss-cloud-probe.yml` (실제 키를 쓰지 않는다).

### 4.3 키는 서버에 저장하지 않는다

`api/_toss.ts` 는 요청마다 전달받은 키를 **메모리에서만** 쓰고 버린다.
폰은 Supabase에 있는 **암호문**을 마스터 비밀번호로 폰 안에서 풀어 들고 있다가 요청 시에만 보낸다
(`lib/keysync.ts` 와 같은 방식). → 클라우드에 평문 키가 저장되지 않는다.

> ⚠️ 그래도 **실계좌 키가 클라우드 서버 메모리를 거친다**는 점은 PC 전용이던 때와 다른 위험이다.
> 그래서 2단계에서도 **읽기 전용(시세·환율)만** 열고, 주문은 데스크톱 앱에만 남긴다.

### 4.4 명령어

```bash
npm run web:dev      # PC 브라우저로 미리보기 (http://localhost:5174)
npm run web:build    # 빌드 → dist-web/  (서비스 워커에 빌드 식별자 새김 포함)
npm run web:deploy   # 빌드 + GitHub Pages(capri-web 저장소)로 배포
```

### 4.5 2단계(시세·환율 자동) — 배포 준비 완료, 올리기만 하면 됨

배포용 파일 트리는 **`deploy/capri-api/`** 에 그대로 들어 있다(그 폴더가 곧 Vercel 프로젝트다).

```
deploy/capri-api/
  package.json      # 최소 설정(빌드 없음)
  vercel.json       # region: icn1(서울)
  api/_toss.ts      # 공용: 토큰 발급·CORS 허용목록·토스 GET
  api/quote.ts      # POST /api/quote  { clientId, clientSecret, symbol }
  api/fx.ts         # POST /api/fx     { clientId, clientSecret }
  api/health.ts     # GET  /api/health (키 불필요 — 배포 확인용)
```

- **필요한 환경변수(env) 없음.** 키는 요청 본문으로 받아 그 순간에만 쓰고 버린다.
  Supabase service role 키 같은 서버 시크릿도 필요 없다.
- 올린 뒤 웹앱에 주소를 꽂는 법: `https://hun100b-dotcom.github.io/capri-web/?api=https://<배포주소>`
  로 한 번 열면 저장된다(설정 탭에서도 바꿀 수 있다). 앱을 다시 빌드할 필요가 없다.
- CORS 허용 목록(`_toss.ts`의 `ALLOWED_ORIGINS`)에 웹앱 주소가 이미 들어 있다.

**로컬에서 먼저 확인하는 법** (배포 없이 진짜 토스와 통신):

```bash
npx tsx scripts/dev-api.mjs     # http://localhost:8787 로 같은 핸들러를 띄운다
# 다른 창에서
curl -X POST http://localhost:8787/api/fx -H "Content-Type: application/json"   -d '{"clientId":"...","clientSecret":"..."}'
```

실측(2026-08-13): 환율 `1418.2`(midRate), `AAPL 302.62`, `NVDA 224.51` 정상 응답.
웹앱 화면에서 버튼을 눌러 화면 → 프록시 → 토스 → 렌더까지 전 구간도 확인했다.

### 4.6 하마터면 조용히 망가질 뻔한 것 (기록)

서비스 워커 파일에 **빌드마다 달라지는 값**이 들어가야 브라우저가 "새 버전"을 알아챈다.
처음엔 그 값 치환이 `web/public/` 복사와 순서가 엇갈려 적용되지 않았고, 게다가
`replace`(첫 번째만 치환)를 쓰는 바람에 **주석에 있던 같은 글자만** 바뀌었다.
→ 배포해도 sw.js 내용이 매번 동일 → **업데이트 배너가 영영 안 뜬다**(에러도 안 남).
지금은 ① 템플릿을 `web/sw-template.js`(public 밖)에 두고 ② 빌드 후 `scripts/stamp-sw.mjs` 가
`replaceAll` 로 새기고 ③ 새긴 결과를 **스스로 검증**해 실패하면 빌드를 멈춘다.
