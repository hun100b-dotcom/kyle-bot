# Capri UI/UX 대업그레이드 — 설계 시안 (2026-08-20)

> **이 문서는 "시안(설계 제안)"입니다. 구현 전에 사장님 확인을 받는 큰 변경만 모았습니다.**
> 벤치마크: 토스증권 · 업비트 · 트레이딩뷰 · 로빈후드 · IBKR (에이전트 리서치 종합).
> 목표: 하나의 React 코드로 **폰(PWA·노치) + PC(Electron)** 를 모두 최고 수준으로.

---

## 0. 큰 그림 — 3단계 무중단 롤아웃

기존 화면을 한 번에 갈아엎지 않고, **토큰 → 컴포넌트 → 레이아웃** 순서로 안전하게 올립니다.
각 단계는 독립 배포 가능하고, 회귀가 나면 그 단계만 되돌립니다.

| 단계 | 내용 | 위험도 | 승인 필요? |
|------|------|--------|-----------|
| A | **디자인 토큰 정리**(색·타이포·간격 변수화) + tabular 숫자 + 라이트/다크 | 낮음 | 방향만 |
| B | **핵심 컴포넌트**(주문 티켓·Big-number·2줄 모바일 표·틱플래시) | 중간 | 시안 확인 |
| C | **레이아웃**(데스크톱 2컬럼 + 탭 통폐합 7개 + 하단 탭바) | 높음(전면) | ★필수 |

## 1. ⚠️ 먼저 정할 것 — 손익 색상 관습 (사장님 결정 필요)

리서치의 **가장 중요한 발견**입니다.

- **미국식(로빈호드): 초록=이익, 빨강=손실.** ← 카프리 현재.
- **한국식(토스·업비트): 빨강=상승/이익, 파랑=하락/손실.** 초록 안 씀.

카프리는 "미국주식인데 사용자는 한국인"이라, 사장님이 **빨강을 손실이 아니라 상승/이익으로 직관**할 위험이 있습니다.

**제안(안전한 절충):**
1. 기본은 지금처럼 **초록=이익 / 빨강=손실** 유지.
2. **설정 탭에 "빨강=상승(한국식)" 토글** 추가 → 켜면 이익=빨강, 손실=파랑으로 스왑.
3. 색맹(남성 8%)·직관 오류 방지를 위해 **부호(+/−)와 삼각형(▲▼)을 항상 병기**(색에만 의존 금지).

> **사장님께:** 기본을 미국식으로 둘까요, 아니면 아예 한국식(빨강=이익)을 기본으로 할까요? — 확인 부탁.

## 2. 단계 A — 디자인 토큰 (지금 바로 가능, 저위험)

현재 `App.css`는 다크 단일 + 색 변수 10개뿐. 이를 **의미 기반 토큰**으로 확장합니다.

### 2.1 색 토큰 (다크 = 현행 유지·정돈 / 라이트 = 신규)

```
/* 공통 시맨틱 (라이트 기본, 다크는 media/​[data-theme]에서 덮어씀) */
--profit  이익   라이트 #05a66a / 다크 #34d399(현행)
--loss    손실   라이트 #f04452 / 다크 #f87171(현행)
--flat    중립   #8b93a7
--primary 포인트 라이트 #3182f6 / 다크 #60a5fa(현행)
--warn    경고   #fbbf24(현행)
--bg / --surface(=panel) / --card / --border / --text / --text-muted
```
- **핵심:** 지금 코드의 `--green/--red/--blue`를 **`--profit/--loss/--primary`로 별칭**만 추가(기존 변수는 유지 → 회귀 0).
- 손익 색상 토글은 `[data-pnl="kr"]`일 때 `--profit`↔`--loss`의 hue만 스왑.

### 2.2 타이포 스케일 (base 16px, 숫자는 tabular)

| 역할 | size/line | weight | 용도 |
|------|-----------|--------|------|
| Display | 34/40 (PC 40/48) | 700 | 총손익·계산기 결과 |
| Title | 20/28 | 700 | 카드 제목 |
| Body | 16/24 | 400 | 본문 |
| Body-sm | 14/20 | 400 | 표 셀 |
| Caption | 13/18 | 400 | ₩ 병기·라벨 |

- **전역 `font-variant-numeric: tabular-nums`** 를 표·리스트 숫자에 적용 → 자릿수 흔들림 제거(리포트·주문현황 필수).
- iOS 자동확대 방지: 입력칸 `font-size ≥ 16px`(현행 유지).

### 2.3 간격·모서리 (4pt 그리드)

`4·8·12·16·20·24·32·40·48` → `--sp-1`~`--sp-9`. 카드 패딩 16, 카드 간격 12, 화면 여백 16(폰)/24(PC). 모서리: 칩 8·버튼/입력 12·카드 16·모달 20.

## 3. 단계 B — 핵심 컴포넌트 (시안)

### 3.1 주문 티켓 (IBKR式 단일 컴포넌트)
계산기의 주문 버튼들을 **한 장의 티켓**으로 응축:
```
[ 매수 | 매도 ]  ← 세그먼트(선택색 profit/loss)
수량 [___] [최대]     가격 [___]
유형 [ 지정가 · 조건주문(OCO) · 진입+익절(OTO) ]  ← 칩
──────────────
예상 체결  $12,340  (₩17,102,600)   ← 자동 프리뷰(현행 계산 재사용)
[🔒 드라이런]              [ 주문 전송 ]
```
- **조건부 마찰**: `canPlaceOrder` 리스크 게이트 미통과·큰 금액일 때만 확인 모달. 안전한 주문은 매끄럽게.
- DRY_RUN 상태는 항상 눈에 띄는 배지. (안전규칙과 정확히 맞물림)

### 3.2 Big-number 스탯 (토스/로빈후드)
리포트·주문현황 최상단에 Display 34px + 카운트업(이미 리포트에 구현됨 → 다른 화면에도 확장) + **스파크라인**(SVG polyline, 의존성 0).

### 3.3 모바일 데이터 표 = 2줄 행 (업비트式)
가로 스크롤 금지. 1행 [종목명 · 손익(색+부호)], 2행 [수량·평단·현재가 muted]. 행 높이 56~64px(터치 44px↑).

### 3.4 체결강도 틱-플래시 (업비트式)
값 갱신 시 셀 배경을 200ms 빨강/초록 fade → "지금 바뀌었다"를 눈으로 스캔 안 해도 인지. (2단계에서 통합 반영)

### 3.5 빈 상태
아이콘 + 한 줄 + CTA 버튼. 빈 흰 화면 금지(리포트는 이미 적용됨 → 삼분할·매매분석에도).

## 4. 단계 C — 레이아웃 (★전면 변경, 사장님 확인 필수)

### 4.1 탭 통폐합 9 → 7 (전수조사 제안)
| 현재(9) | 제안(7) | 변경 |
|---------|---------|------|
| 계산기 | 계산기 | 유지 |
| 📊 매매리포트 | 📊 리포트 | 유지 |
| 탐색 | 탐색 | 유지(3단계 보강) |
| 내 삼분할 기록 | 기록 | 삼분할+계산기 기록 통합 |
| 체결강도 + 매매분석 | **체결강도** | ★2탭→1탭 통합(2단계에서) |
| 주문현황 | 주문현황 | 유지 |
| 기록(journal) | → 설정 안 "진단" | 상단 탭에서 제거 |
| 설정 | 설정 | 유지 |

### 4.2 데스크톱 2컬럼 (트레이딩뷰式)
PC(≥1024px)에선 탭 전환 대신 **좌(입력/계산기) + 우(리포트/주문현황) 동시 표시**. 같은 코드에서 `@media`로만 분기.

### 4.3 폰 하단 탭바
주 5개 고정 + "더보기". 높이 56px + `env(safe-area-inset-bottom)`. 활성만 primary.

---

## 5. 모바일 Safe-area · 터치 규칙 (이미 상당 부분 적용됨 → 표준화)
- `viewport-fit=cover` + `env(safe-area-inset-*)` (현행 유지).
- 터치 타깃 **최소 44×44 / 권장 48**, 인접 8px.
- 되돌리기 어려운 [주문 전송]은 56px + 확인.

## 6. 권장 착수 순서
1. **A(토큰)** — 저위험, 즉시. 별칭 추가라 회귀 0. → 폰·PC 즉시 배포.
2. **B(컴포넌트)** — 시안 확인 후 하나씩(주문 티켓 → 2줄 표 → 틱플래시).
3. **C(레이아웃·탭 통폐합)** — 사장님 최종 확인 후. 체결강도(2단계) 확정과 함께.

> 이 시안 중 **1번(손익 색), 4.1(탭 통폐합), 4.2(2컬럼)** 은 사장님 확인이 필요합니다.
> 나머지(토큰·tabular·주문티켓·2줄표·빈상태)는 확인되면 바로 착수합니다.
