# 손익색 반대 버그(#3) + 탐색→계산기 자동입력(#6) — A/B 교차 리뷰 (2026-08-21, v0.16.0)

사장님 강한 불만: "이익 빨강 설정했는데 색이 반대로 나온다"(기본 실패) + "탐색 종목 클릭 시 전봉종가·EMA200 자동입력".

## #3 손익색 반대 — 원인·수정
- **원인:** P&L 표시가 두 갈래 — 리포트(.up/.down)·보유·주문(pnlClass)은 토큰(--profit/--loss)이라 토글에 뒤집히나,
  **매매분석 결과%가 `resultPct>=0?"ok":"danger"`**(원색 --green/--red 직결)라 안 뒤집혔다 → 한 화면에
  "빨강=이익"과 "빨강=손실"이 공존 → 사장님 눈엔 반대/뒤죽박죽.
- **수정:** ① 매매분석 결과%를 `pnlClass`로 통일 ② 설정 토글 라벨의 색 견본이 반대(빨강 글자가 파랑으로)라 고정 hex로 교정.
- **리뷰 확인:** 남은 `ok/danger`는 전부 비-P&L(체결강도 100기준·스크리너 근접도)이라 뒤집으면 안 되는 것 → 조치 불필요.
  리포트·주문현황·매매분석·보유 P&L 전부 토큰 일관.
- **라이브 검증(실데이터 주입):** AAPL +10%/TSLA −5% → 미국식(초록/빨강), 한국식 토글 → 이익 빨강·손실 파랑 정확.

## #6 탐색→계산기 자동입력 — 구현
- 엔진 `scanScreener`가 ScreenResult에 `prevClose`(마지막 완성 5분봉 종가) 추가. `pickScreenSymbol(r)`가
  종목+전봉종가+EMA200을 계산기(삼분할)에 자동 채움(수정 가능). 테스트로 prevClose 채워짐 검증.
- **A/B 리뷰:**
  · (반영) autoLoad→refreshCapacity가 stale `symbol` state로 수량 조회 → 행 클릭 시 방금 고른 종목이 아직
    state에 없어 이전 종목 수량을 조회하던 선재 버그. `symOverride`로 넘겨받은 종목 조회하게 수정.
  · (수용) setTech("split3")는 의도된 방식 전환(자동입력 값이 삼분할용). HA-EMA200 vs raw-prevClose 기준 혼합은
    선재 특성이고 $1~9 밴드에선 오차 작으며 사용자 수정 가능 → 저위험 주의사항.
  · prevClose null-safety OK(insufficient/error 행은 undefined, `!= null` 가드).
