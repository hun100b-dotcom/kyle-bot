# 리포트 기간필터 정확도 — A/B 교차 리뷰 (2026-08-20, v0.10.1)

오너 지적: "매매 리포트 기간별 설정했을 때 해당 기간에 맞는 매매를 정확히 뽑아라."
전수조사에서 원인을 찾고(8페이지 상한 + 깊이 모르는 캐시), 고친 뒤 Reviewer A(총괄)·B(적대)로 교차검토.

## 근본 원인 (전수조사)

| # | 문제 | 근거(코드) |
|---|------|-----------|
| 1 | 토스 종료주문을 **8페이지(≈160건) 고정 상한**에서 끊음 → 매매 잦으면 30일치가 안 들어와 옛 매매 누락 | `collectFills` `for (page<8)` |
| 2 | 상한에 걸려도 `partial` 미표시(예외일 때만) → 조용히 잘림 | `partial`은 catch에서만 true |
| 3 | 60초 캐시가 **깊이를 모름** → "오늘"(얕게) 캐시 후 "1개월"(깊게) 재사용 | `fillsCache`에 깊이 정보 없음 |

## 1차 수정 → A/B 리뷰가 잡은 회귀 (핵심)

1차로 (ⓐ상한 8→40, ⓑ`coveredSince`/`cacheCovers` 순수함수로 깊이인지 캐시)를 넣었더니
**A와 B가 독립적으로 같은 회귀 2건을 HIGH로 지목**:

| # | 발견 | A | B | 합의 | 최종 결정 |
|---|------|---|---|------|-----------|
| R1 | 잦은 매매자는 40페이지 상한에 걸려 캐시가 얕게 잡히고, 리포트는 항상 45일↑ 요구 → **매 버튼마다 재조회 = 429 폭풍**(60초 캐시 무력화, 옛 8페이지보다 나쁨) | MEDIUM | HIGH | **합의** | **FIX**: `shouldReuseCache` — 재조회가 실제 이득일 때만(캐시가 더 깊이 갈 수 있는데 더 깊이 필요할 때만). 그 밖엔 60초 재사용 |
| R2 | `report()`가 `partial`을 버림 + `DailyReport`에 필드 없음 → **잘린 손익/승률이 표시 없이 나감** | LOW-MED | HIGH | **합의** | **FIX**: `truncated` 필드 신설 + 화면 경고. 단 누적 저장본까지 봐서 '진짜 빠졌을 때만' |
| R3 | 오프라인 실패 캐시(covered=+∞)도 재사용 안 됨 → **끊긴 곳에서 재호출 난타**(예전 ~10s 스로틀 사라짐) | — | MEDIUM(B단독) | B단독(핵심) | **FIX**: `shouldReuseCache`가 canDeepen=false면 재사용 → 스로틀 복원 |
| R4 | `Date.parse(filledAt)` 호스트 TZ 의존 | LOW | — | A단독 | 오탐(타입=ISO+KST, 오프셋 포함 → Date.parse 정확). 조치 없음 |

### A/B가 "깨보려다 실패"로 확인한 것 (정상)
- `cacheCovers`의 `>=` 방향·경계 정확(과다 재사용으로 매매 누락 없음).
- `page>=MAX_PAGES` partial 판정: break 경로/정상완료 모두 오탐·누락 없음.
- 빈 계좌(oldestSeen=+∞) → coveredSince=+∞ → 강제 재조회 정확.
- 정상 today→month 심화는 재조회, month→today는 재사용(깊이 구멍 없음).

## 최종 FIX (2차)

1. **`shouldReuseCache(cache, sinceMs, now)` 순수함수** — "재조회가 이득일 때만"(needDeeper && canDeepen)
   재조회, 그 외 60초 재사용. `canDeepen = reachedTarget`(일찍 멈춤만 더 얻을 수 있음; 상한·끝·실패는 false).
   → R1(429 폭풍)·R3(오프라인 난타) 동시 해결.
2. **깊이 통일(deep-floor)** — `report()`가 `min(기간필요깊이, now-75일)`로 조회 →
   오늘/1주일/1개월을 **한 번의 깊은 조회**로 커버(60초 재사용) → 버튼 오가도 재조회 안 함.
3. **정직한 `truncated`** — 이번 조회가 상한에 걸렸고(fetchPartial) **저장본도 기간 앞부분을 못 덮을 때만** true.
   `TodayReport`가 이때만 빨강 경고. 누적 저장본이 덮으면(평소) 조용 → 오탐 방지(A의 지적 반영).
4. 저널 문구도 "빠질 수 있음"(단정) → "저장된 기록은 유지됩니다"(사실)로 완화.
